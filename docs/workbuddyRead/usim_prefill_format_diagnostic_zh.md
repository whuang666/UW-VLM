# USIM 前缀续写格式诊断方案

日期：2026-10-28（Asia/Shanghai）。选择方案 A，先验证前缀续写兼容性，再按固定题集诊断。当前尚未实施该请求变更或调用 API；294 次全量继续暂缓。

## 请求与输出约定

阿里云[前缀续写官方文档](https://help.aliyun.com/zh/model-studio/partial-mode)列出 Qwen3.8-Max 非思考模式支持 Partial Mode。末条消息应为：

```json
{"role": "assistant", "content": "[", "partial": true}
```

文档的代码示例将 `prefix + generated_code` 作为完整回答。因此固定约定：`completed_answer = "[" + raw_completion`。保存原始响应、原始续写文本、固定前缀及拼接后的完整回答；使用完整回答调用原 v0.3 严格解析器与已冻结副指标。不按解析结果决定是否补括号、不去掉重复前缀、不截取最后一个列表、不读 gt 选择拼接策略。

预填一个 `[` 仍可能产生非法内容或额外文本，它不是 JSON Schema 约束。该操作增加 assistant 上下文并改变请求结构，即使用户题干不变也属于新的请求协议；不得把它描述为“没有改变提示上下文”或“保证只能输出合法列表”。正式诊断前冻结新的请求、拼接、预算和源码约定；保持已有主、副评分规则不变。

1. **单题兼容性冒烟**：取原16题中按固定顺序的首道 forward L4，使用 B 的四张复合图、2048预算、thinking=false、原模型与接口；仅追加上述 assistant 消息。核验接口接受 Partial Mode 与多图，记录返回是否只含续写、停止原因及固定拼接后的严格合法性。该1次请求单独保存，不计入正式诊断指标；不因答案错误改配置。
2. **固定16题 × A/B**：新 run 建议为 `v02_prefill2048_diag_v1`，共32次逻辑请求。ID、顺序、图片、原用户题干、模型别名、接口、temperature=0、thinking=false和2048预算与上一轮对齐，仅改变明确记录的前缀续写请求。凭据由用户持久环境读取，既不输出也不落入产物。

只有单题兼容性通过且新请求约定已冻结后，才进入32次诊断。若接口不支持或前缀拼接不符合文档，保留错误证据并停止，不在同一 run 内静默换成 system message、换模型或修改拼接规则。

判据继续是零 `length`、零缺失／传输失败、严格合法率100%；同时报告副指标，EM不参与选择。所有失败保留在分母，不重试格式错误以覆盖原分数。通过也只支持这16题；294次及最终 test 的执行协议另行冻结。
