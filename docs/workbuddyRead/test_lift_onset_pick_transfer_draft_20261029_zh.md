本草案把物体离底事件、机器人高度信号和最终选帧条件分开定义。pick 与 transfer 沿用同一套 `OnSeabed` / `InGripper` / `Lifted` 物理语义，区别在搜索阶段及辅助证据。1378 的技术复核记录说明 DVL 代理可以失效；单条反例尚不能证明所有 transfer 都会失效，也不能证明 pick 中的代理均可靠。

## 2. 统一术语：三个时点不能混用

| 字段 | 定义 | 能说明什么 |
|---|---|---|
| `robot_rise_proxy_frame` | 机器人 `observation.state[28]` 达到预定阈值并持续的首帧 | 信号定位点；可能滞后于物体离底，也可能落在运输阶段 |
| `object_departure_bracket` | 同一次抓取中，最后可确认仍受沙面支撑的保持段，与随后首次可确认已脱离支撑的保持段之间的区间 | 物体离底发生的视觉时间范围；不伪造精确物理起点 |
| `gap_ready_hold` | 首个满足最终 `Lifted` 证据要求的稳定保持段 | 可候选的 lift 状态；不自动等于 onset |

`Lifted=true` 的共同证据要求：目标被实际持有，**整个物体的最低点**与所在沙面之间有可辨间隙，约不小于目标短边半宽。管子检查最低管端，短边参考管径；不能用管子中段离地代替管端离地。

按原生 ego 图记录目标最低点、参考沙面和宽度依据。透视、遮挡、无纹理沙面或物体出画使判断不可靠时，记录 `unresolved`；DVL、夹爪命令和腕相机作为辅助。这里是视觉证据标准，不声称从二维像素恢复了真实物理高度。

### 2.1 视觉 onset 的操作定义

按真实时间顺序查看同一次抓取的原生 ego 渲染保持段：

1. 找到最后一个可确认物体仍受沙面支撑、且此后没有松开重抓的保持段 A。
2. 找到 A 之后首个可确认物体与沙面已经分离、且物体仍被持有的保持段 B。初次分离可以尚未达到半宽；半宽条件在选取 `gap_ready_hold` 时另验。
3. 以 `object_departure_bracket = (A.end, B.start]` 记录可见证据约束的区间，并保存 A、B 的原生图与源帧哈希。B.start 是“首次观察到分离”的界限，不称为精确物理 onset。
4. 如果中间有无法判读的画面，保留区间与缺口；如果缺 A、缺 B、目标最低点不可见，或发生放开重抓，onset 保持未决。先按抓取尝试分段，再单独复核。

重复帧不构成新的运动证据。持有关系仍需接触及相邻独立渲染画面的共同运动支持，不能从一张静止图或闭合信号单独确认。

## 3. Pick 草案：`pick_visual_departure_draft_v1`

适用：pick pipe / blue cylinder / red cylinder 的同一次主抓取。

| 项目 | 拟议规则 |
|---|---|
| 起始范围 | 实际抓取附近开始，保留确认支撑状态所需的前序 ego 保持段；多次尝试先分段 |
| onset | 按 §2.1 记录物体离底区间 |
| DVL 用途 | 用 §5 的诊断定位点建议查看范围，同时检查定位点之前的首次离底；不把超过高度阈值视为物体已经离底 |
| 搜索终点 | 首次释放、失去持有证据、目标最低点持续不可判，或视频结束；再次抓取视为另一尝试 |
| lift 候选 | 按时间顺序找首个符合 §2 物理证据及 §6 稳定性要求的 `gap_ready_hold` |
| 无可用候选 | 记录原因；评估剩余 start / approach / grasp 能否支持 L=3，或排除 |

1259 的 close159 → open186 → close190 必须保留尝试边界。实际持有从画面独立判断；既不能把信号高位写成持有，也不能把第一次尝试的支撑证据无说明地接到第二次抓取的 onset。

## 4. Transfer 草案：`transfer_visual_departure_draft_v1`

适用：抓取后向绿箱搬运的 episode。物体离底定义和半宽标准与 pick 相同。

| 项目 | 拟议规则 |
|---|---|
| 阶段划分 | 支撑／抓取 → 初次离底 → 搬运／可能下降 → at_box → release；阶段从图像证据标识，不用任务文字自动赋值 |
| onset | 只在同一次抓取的**初次离底阶段**按 §2.1 建立物体离底区间 |
| 搬运起点 | 记录机器人／末端与绿箱相对位置开始持续改变的视觉证据区间；不能仅用 DVL 上升来界定 |
| DVL 用途 | 辅助核对机器人运动；不替代物体最低点与沙面的视觉证据 |
| 独立 lift 状态 | 需在初次离底至搬运阶段交界附近找到可判、稳定、与 grasp 及 at_box 有非空语义差异的状态；不能从晚段下降画面倒推早段已满足 `Lifted` |
| 阶段混合／缺帧 | 明确记录阶段边界未决；不把后续 DVL 回升自动当成新的初次离底 |
| 降级路径 | 若独立 lift 状态无法成立，评估 start → approach → grasp → at_box 的 L=4；每个保留状态与跨段转移重新验收 |

1378 的 f290 按现有记录比 f250 更难确认间隙，属于需要隔离运输阶段的反例。它不证明全条 episode 没有离底，也不证明所有 transfer 的阈值窗口都不可用。

`NearBox=true`、箱体可见或闭合信号高位，都不能单独证明 at_box 帧的 `Lifted=true`。1378 若删 lift 保留 at_box，仍要逐谓词确认该末帧的持有与离底，复核 grasp→at_box 的 ego 可判性、非空差分及全局答案有效性。不能把“at_box 位置成立”当作该帧全部事实已经验收。`InBox` 继续按原规范单独判定。

## 5. 已有 DVL 窗口的精确诊断定义

本节用于重现与解释窗口表，命名为 `robot_rise_proxy_diagnostic_v1`。它是历史诊断定义，未升级为正式物体 onset。

帧号从 0 开始；长度 N 的有效帧为 `[0, N-1]`。`h[i] = observation.state[i][28]`；0.05 / 0.02 保留为该字段原始数值单位，本草案不假定其为米。缺测或非有限值时诊断未决，不填补。

- 夹爪闭合信号：`state[0] > 0.004`。当前探针以最后一次 close 为候选 c；正式使用前须确认它属于主抓取尝试。
- 最低点搜索范围：Python 半开区间 `[max(0,c-20), min(N,c+120))`。相同最小值取最早帧 m。
- `b = h[m]`；阈值点 t 是 m 之后首个满足以下条件的帧：`h[t] >= b+0.05`，且后续 **10 个完整样本** `h[t+1:t+11]` 全部 `>= b+0.02`。样本不足时不缩短持续要求。
- 原始窗口 `W_raw = [t+40,t+60]`，可用部分 `W_available = W_raw ∩ [0,N-1]`。交集为空即该诊断窗口不可用；不能把起点挪到末帧、复制末帧或补齐视频。
- 部分交集保留原始窗口及截取原因；仅在交集内查候选，不从窗口外搬入画面。整个窗口不可用与“episode 没有 lift”是两种结论。

### 5.1 可复核的只读计算片段

以下假定 `state` 已从指定 episode 的原始 Parquet 读取为浮点数组；不写文件、不赋标签。该片段只定义诊断计算，未改推理或标注器。

```python
import numpy as np

closed = state[:, 0] > 0.004
closes = np.flatnonzero(closed[1:] & ~closed[:-1]) + 1
if not len(closes) or not np.isfinite(state[:, [0, 28]]).all():
    raise ValueError("Missing close event or non-finite source signal")
c = int(closes[-1])
n = len(state)
lo, hi = max(0, c - 20), min(n, c + 120)
m = lo + int(np.argmin(state[lo:hi, 28]))
b = float(state[m, 28])
t = next((i for i in range(m, n - 10)
          if state[i, 28] >= b + 0.05
          and np.all(state[i + 1:i + 11, 28] >= b + 0.02)), None)
raw = None if t is None else (t + 40, t + 60)
available = None if raw is None else (max(0, raw[0]), min(n - 1, raw[1]))
if available is not None and available[0] > available[1]:
    available = None
```

## 6. 拟议选帧策略与版本变更

**本草案建议：新 release 统一按物体视觉离底及首个合格稳定状态选帧，把固定 DVL+40–60 窗口保留为诊断对照。** 这改变了现行 §3.0 的硬性选帧规则，尚未生效；不能把候选标为已满足旧规范。

拟议策略 `first_visual_gap_ready_hold_draft_v1`：

1. 在 §3 / §4 的正确阶段按时间顺序列出保持段；为每段记录原生 ego 证据、最低点可见性、持有／支撑／间隙判断。
2. 候选保持段长度至少8帧，整个拟用状态可判；相邻关键帧至少相隔25帧，且独立检查至少跨越2次渲染更新。帧距不能替代更新次数。
3. 选首个全部满足视觉及结构条件的保持段，在该段合格帧中取最接近段中点的一帧，等距取较早帧。若没有合格帧，保留未决或评估降级；不按模型答案或所需题长选择。
4. 仅达到半宽间隙不够：所有 scope 谓词、visibility 及相邻转移均需独立核对。未知值只留在复核表，不能自动编译为 false；无法全程判定的谓词按原规范从整条 episode scope 移除后重新验收。

稳定性口径也须在正式修订中明确：原规范一般条文写“前后≥10帧”，事件锚定条文使用渲染保持段；当前技术预检多用≥8帧。这些表述不能自动视为等价。本草案建议采用明确的保持段长度与渲染更新规则，生效前需统一核验。

当前探针保持段按相邻灰度图平均绝对差 `>0.5` 分段，不能称为“所有帧逐字节相同”。后续记录方法、阈值、段边界和源帧哈希；不要混用精确像素哈希分段和运动阈值分段的长度。

若最终选择保留40–60硬窗口，则须另行固定物理／信号锚点和区间转单点方式，再对全部适用条目检查。不能临时为某条更换锚点、取区间端点或改窗口宽度。
