## 4. 三条必须带进论文的结论

1. **inverse 方向不构成视觉证据。** 程序文本基线不看图就能答对 55/84；A、B 在 inverse L3–L5 全部 1.0000，C 也有 0.8571–1.0000。视觉证据只能来自 forward L≥4、条件 D，以及「基线答错」层的配对差值。
2. **去图后不如一个正则式启发式。** C（0.5952）低于程序文本基线 text_prior（0.6583），且在「基线答错」层只有 0.1379。把 C 当作「模型的文本能力」会高估它——它连固定模板的文本线索都没用稳。
3. **A−B 的差距不能读成「局部放大损害感知」。** A−B 的 8 例差异中 **7 例是 B 侧 256 token 截断**，仅 1 例（`1318/…4db57cf9`）是真实排序错误；B 的「基线答对」层反而 **1.0000 > A 的 0.9818**，跌落全部发生在「基线答错」层。
   **但也不能反过来说「全部差异都由预算造成」**：9 条无效里只有 1 条（`1304/…ccfd8e4e`）被人工通读确认推理链正确，其余 8 条未被逐条核验；且给足预算后它们是否都能答对，本实验未测。可支持的表述只有一句——**B 的严格 EM 混杂了输出预算效应，在读作感知指标之前必须先做预算诊断。**

## 5. 输出预算混淆（诊断，非官方分数）

| 条件 | invalid | `finish_reason=length` | 说明 |
|---|---:|---:|---|
| A | 0 | 0 | 全部 `stop` |
| B | **9** | **8** | 8 条散文推理被 256 token 截断；1 条容错格式（`[1]` 长度不足） |
| C | 0 | 0 | 全部 `stop` |
| D | 0 | 0 | 全部 `stop` |

机制：B 的 640×240 宽幅复合图诱发冗长推理，256 token 预算在输出最终排列前耗尽 → 解析失败 → 按 v0.3 记 0（**评分正确，不需要也不允许事后改分**）。

边界：只有 1 条截断输出被人工通读（推理链正确、在 Action 3 处被切断），其余 7 条截断与 1 条列表长度错误**未逐条核验**，也没有做「同题加大预算后是否答对」的对照。因此本节只支持「B 的严格 EM 被预算污染」这一判断，不支持「B 真实能力与 A 相当」。

**后续实验已补上这一对照**：§13 在同一 16 题上把预算提到 1024，截断从 4 条降到 1 条，同时暴露出 2 条「答案正确但格式不合规」——即预算只能解释一部分，格式服从是另一个独立问题。

单例证据（`usim_train_episode_001304_forward_world_modeling_4_steps_ccfd8e4e`，gt `[3,2,1]`）：模型逐条给出「Action 1 → Next State 3」「Action 2 → Next State 2」，内容正确，但在输出最终列表前被截断。因此 B 的低分是**格式/预算交互**，不是感知退化；要得到可解释的 B 数字，必须在更大预算下**独立重跑**（见 §8）。

## 13. 1024-token A/B 配对诊断（2026-10-28 实跑，gate 未通过）

|---|---:|---:|---:|---|---:|---:|---:|---|

同一 16 题在历史 256 预算下的对照（`historical_256`）：A 仍 100%；B 为 `length 4`（25%）、严格合法 12/16（75%）。

### 13.1 关键发现：失败模式被预算"转换"了，但没有消失

| 预算 | B 的无效数 | `length` 截断 | `extra_text`（格式） | 其中**结尾已有合法列表** |
|---|---:|---:|---:|---:|
| 256（同 16 题） | 4 | 4 | 4（与截断重合） | 0 |
| 1024（同 16 题） | 3 | 1 | 3 | **2** |
| 256（全 84 题，历史） | 9 | 8 | 8 | 0 |

- 256 → 1024 把截断从 4 条压到 1 条，说明**预算确实不够**，加大有效；
- 但 1024 下剩下的 3 条里有 **2 条是 `stop` 正常结束、且结尾已输出正确列表**（`…45a760d1` 结尾 `[3, 2, 1]`、`…827185aa` 结尾 `[4, 1, 2, 3]`，后者与 gt 一致），只因前面写了推理散文而被 v0.3 判 `extra_text`；
- 剩下 1 条（`…cda525ee`）到 1024 仍在推理中途被截断。

**结论：预算不是唯一原因。** 1024 下仍有 1 条截断，"零截断"这一条判据本身也没达成；另外 2 条则是**已保存的输出**无法通过严格解析（它们不是"想不出答案"，而是"答案对了但没按格式只说列表"）。**注意边界**：本轮只能断言"这 2 条已保存的输出过不了严格解析"，**不能**推断"换更大预算也救不回来"——重新请求得到的是新样本，其行为尚未测量。

**新增的 `extractable_permutation_v1` 副指标不影响本判据**：它把 1024 下 B 的可解析数从 13/16 提到 15/16（见 §14），但这只是**解释**这些 0 分的来源，不代表预算达标，也不把 `fail_on_fixed_subset` 改判为通过。

与 A 的对照仍然成立：A 的 `completion_tokens` 观察最大值只有 **13**，即 A 从不触发啰嗦；宽幅复合图 B 诱发的冗长推理是条件特异现象。

### 13.2 因此 gate 判定为不通过，且不建议直接按 1024 跑 294 次

按预注册判据（只看零截断 / 零缺失 / 严格合法率 100%，**不看 EM**），B 的两项都不达标。若此时以 1024 跑统一四条件，B 仍带 3/16 的格式性 0 分，产出表依旧无法区分"感知"与"格式"。

三条可选路径（需在 test 前定稿，且必须对**所有条件**同规则生效、可追溯）：

| 方案 | 做法 | 代价 | 风险 |
|---|---|---|---|
| **① 保持 v0.3 主指标，另报"可提取"副指标** | 新增 v0.4：允许"散文 + 结尾单个合法列表"被提取；主指标仍 v0.3 | 低（只改分析层，A/C/D 不受影响） | 副指标须在 test 前预注册，否则像为 B 松绑 |
| ② 加强格式约束后重跑 | 如 assistant 前缀预填 `[`、或在题干再加硬约束 | 中（属 prompt 变更，四条件全重跑） | 改变协议，需新 freeze_id |
| ③ 接受格式失败为被测行为 | 不修，B 的格式不合规本身作为结论报告 | 零 | 论文只能说"B 更易不合规"，不能说感知差异 |

**最终决定**：选择①，副指标独立命名为 `extractable_permutation_v1`，保留 v0.3 主指标。1024 仍有 1/16 截断，不能认定为通过或作为已冻结的统一预算；294 次重跑暂缓。现有开发集分析保持事后探索标记，最终 test 的运行协议仍需另行冻结。

> 2026-10-28 晚：用户已拍板走路径①，`extractable_permutation_v1` 已实现（§14），294 次重跑继续暂缓。

### 13.3 2048 预算诊断：截断归零，格式失败不动 → 停止加预算

同一 16 题、同一图片/prompt/解码，仅预算 1024→2048（新 run `v02_budget2048_diag_v1`，`plan_sha256=1bb9f1df…`，32 次请求，3 分 07 秒，`state=complete`）。

| 预算 | 条件 | 截断 `length` | 严格合法 | 副指标可提取 | `completion_tokens` 观察最大值 |
|---|---|---:|---:|---:|---:|
| 256（历史） | A | 0 | 16/16 | 16/16 | 13 |
| 256（历史） | B | **4** (25%) | 12/16 | 12/16 | 256 |
| 1024 | A | 0 | 16/16 | 16/16 | 13 |
| 1024 | B | 1 (6.25%) | 13/16 | 15/16 | 1024 |
| **2048** | A | 0 | 16/16 | 16/16 | 13 |
| **2048** | B | **0** | **13/16** | **16/16** | 1968 |

三点结论：

1. **截断确实由预算解释**：B 从 4 → 1 → 0，预算加到位就消失。但 2048 下 B 的最大用量是 **1968/2048**，余量只剩 80 token——这条头部回答已经贴着上限。
2. **严格格式失败与预算无关**：2048 下 16 条全部 `stop`，仍有 **3 条 `extra_text`**，且这三条与 1024 时是同一批（`…ea4ca751`、`…45a760d1`、`…827185aa`）。它们的结尾都给出了合法列表（`[3,1,2]`、`[3,2,1]`、`[4,1,2,3]`），**全部等于 gt**。
3. **因此原 gate 仍判失败**（`fail_on_fixed_subset`，exit 3）：判据要求严格解析零失败，而这条要求加预算无法满足。

按预注册决定：**到此停止增加预算**，下一步转向"格式约束"的独立版本诊断。2048 也不作为统一预算（`plan` 里未定，`unified_output_budget` 仍为空）。

A 与 B 在 2048 上的副指标口径完全一致（均 16/16 可提取、`EM_extractable` 均 14/16 = 0.8750）。这可以用来说明"严格口径下的差距在 2048 下主要来自格式"，但**不能**据此宣称 B 的感知与 A 等同——16 题、单 run、且副指标本身不是感知指标。

## 14. 副指标 `extractable_permutation_v1`（2026-10-28 已独立冻结）

主指标 `usim_strict_v0.3` **保持不变**；本副指标是独立版本，回答一个更窄的问题：*正常结束的回答里，能否恢复出一个合法排列。*

### 14.1 冻结规则（原文即约束）

| 条目 | 规则 |
|---|---|
| 资格 | 仅接受成功返回且 `finish_reason == "stop"` 的回答；`length` 截断、缺失、失败一律 0 |
| 位置 | 全文**只有一处**方括号列表，且位于回答**末尾**（其后只允许空白） |
| 内容 | 该列表必须是整数、长度正确、构成 `1..(num_states-1)` 的排列；候选完整字符串直接交给 `USIMEvaluator.parse_strict` |
| 计数 | 多候选 → 0；提取过程**不读 gt**；规则对所有条件一致；**分母始终是全部题目** |

「末尾」按保守解释实现：`[2, 1, 3].`（带句号）判 `list_not_at_end`，不做标点容忍。若日后要放宽，属 v1.1 变更，需重新预注册。

### 14.2 实现与测试

- 模块：`scripts/usim/extractable_v1.py`（`VERSION = "extractable_permutation_v1"`），`extract(text, finish_reason, expected_length)` 返回 `status/permutation/reason/list_count`；签名里**没有 gt 参数**。
- 长度口径：`expected_length = num_states - 1`（来自题目结构，不读答案键），并断言与 `len(gt)` 一致，否则直接报错。
- 只读分析脚本：`scripts/usim/report_extractable_v1.py`。初版 `_protocol/extractable_v1/` 报告保留；冻结后的新报告另存 [evidence/extractable_v1_20261028/](evidence/extractable_v1_20261028/)，显式标注 `post_hoc=true`、`frozen=true`、`affects_budget_gate=false`。这里的 frozen 只表示规则已核验，不会使开发分析变成事前实验。
- 冻结清单：[extractable_permutation_v1.freeze.json](../protocols/extractable_permutation_v1.freeze.json)，编号 `20261028_extractable_v1`，payload `b7290ef1e4e6b6e0f4ee1971f2af0e102d7b69e1f19b5249479ecfe747569e9e`；[规范](../protocols/extractable_permutation_v1.md)列明标点、长度、资格和完整分母。冻结8个文件，包含直接复用的原主解析器。
- 冻结前发现并修复初稿的两处边界遗漏：多余／未闭合方括号可能被正则跳过；分析层未校验成功状态。另补重复／未知 ID、冻结 QA 哈希与评分条目全覆盖检查，避免静默缩小分母。
- 测试：提取25项、分析完整性及326条历史响应回归10项、冻结／篡改检查5项；相关40项及全量54项全部通过。既验证裸列表与主解析器等价，也验证真实调用主解析器。原主评分器及1818文件主冻结均核验通过。

### 14.4 使用边界

2. 副指标已独立冻结：规则、源码和测试清单锁定；以后行为变更须单独版本化。最终 test 的题集、模型、提示和预算不在本次冻结范围内，仍须事前另行冻结。
3. 论文中必须主副并列：主指标 v0.3 用于结论，副指标用于说明"0 分里有多少是格式而非答案"。不得只报副指标。
