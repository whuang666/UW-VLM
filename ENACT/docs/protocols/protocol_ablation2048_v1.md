# 双协议开发对照 v1：P0运行与验收契约

本契约用于新版本 no_prefill / prefill × A/B/C/D 开发矩阵。当前预算2048是实验控制值，不是正式test的已定统一预算。原主评分器、副指标、历史预测和旧冻结文件保持原样。

## 范围与阶段

生产dev输入为A/B/C各84题，D为A完整forward42题子集；两个协议共588次逻辑请求。每个条件的两协议使用同一题干、显示图像与解码，只追加固定assistant消息；C实际不发送图像。

默认prepare只生成计划、QA副本、每单元配置、588份请求摘要及候选冻结，不读取密钥、不发请求。候选冻结覆盖本契约、运行器、独立核验器、共享离线定义、测试、原主请求构造器和主副解析器、输入与图像摘要。

生产计划还从已核验的主冻结继承评分代码依赖、相关episode的标签／场景图／源帧摘要与来源清单，防止QA未变但语义评分依赖漂移。单元测试中的临时fixture不作为生产实验。

显式execute首先完成8次独立兼容性冒烟（两协议×四条件），并核验来源与完整性；无预填控制的散文不视为接口不兼容。预填冒烟必须正常停止且严格合法，无前缀回显。只有8项兼容性均通过，才独立创建execution冻结，锁定候选清单及原始冒烟证据，然后执行正式588次。`--smoke-only`在8次后停止。冒烟不计正式分母，EM不参与选择。

## 请求与评分

前缀消息固定为 `{"role":"assistant","content":"[","partial":true}`。成功返回的非空原始续写按字面拼接：`completed_answer = "[" + raw_completion`；无预填的完整答案等于原始正文。不得按解析结果补括号、去重复前缀或挑选列表。缺失正文另记invalid，不能补造答案。

主指标直接调用原v0.3解析器；副指标调用已冻结的 `extractable_permutation_v1`。提取的期望长度来自 `len(key_frame_ids)-1`，函数不接收gt。HTTP失败和invalid状态的主评分输入为None，与原预测加载器一致；截断即便恰有可解析列表，预算gate仍失败，副指标计0，主解析器行为不更改。

每次请求保存JSON对象规范化摘要和实际传入HTTP层的序列化字节摘要，二者名称分开；记录每次原始HTTP响应字节（Base64）、完整解析payload、来源绑定、时间、usage、request_id、原始续写与派生文本。密钥仅放Authorization请求头，不写日志或产物。客户端摘要是本地可重建证据，不冒称服务端独立证明。

## 重试、续跑与中断

只对网络错误及冻结的408/409/425/429/500/502/503/504最多尝试3次；200下的格式失败、答错、截断均不重试。400/401/403/404/422停止整个运行。所有传输尝试和响应保留。

有已有证据时必须显式resume；已形成终态预测的ID，包括失败、截断、格式错误，均不重新请求。任何配置、QA、图片、源码漂移、重复／未知ID在读取密钥或发请求前拒绝。存在未决inflight或孤立的尝试／响应时停止，不自动重发可能已收费的请求；保留文件供恢复裁决。

## 独立核验

默认核验范围为complete_run：要求每单元ID集合等于冻结QA，所有尝试与原始响应一一对应，完整重建预定请求数，逐条重做拼接、主副解析和元数据核对。文件漂移与请求重建独立报告；后者不能抵消前者失败。空结果不能通过完整核验。

显式prepared_inputs仅核验候选输入和源码，`execution_verified=false`；内部partial_evidence仅支持安全续跑，不作为完整运行通过的证明。

analyse要求完整运行证据通过，使用stock evaluator对每个完整QA子集评分，结果写新运行的analysis目录，原预测不改。缺失、失败和不可解析结果始终保留在预定分母。格式gate与完整性gate分开，无预填控制的格式失败不导致删除该控制条件。

## 版本边界

冻结后修改本契约或被锁定源码需新版本与新运行目录。候选冻结可在离线阶段创建，execution冻结只能在8次冒烟证据通过后创建；没有真实冒烟时不声称已获正式执行准入。P0的离线单元测试使用临时目录和模拟传输，不作为真实API结果。
